# Tool Inventory

Every tool the Rise-X MCP server exposes, grouped by category, with signatures
and per-tool caveats.

90 tools. Mutations accept `response_format="summary"|"full"` (summary is the
default and carries verification warnings).

| Category | Tools |
|---|---|
| **Session** (4) | `list_ecosystems`, `set_active_ecosystem`, `get_active_ecosystem`, `whoami` (bound user + ecosystem + deployment — use when visibility looks wrong) |
| **Flow** (9) | `list_flows(flow_resource_type?)`, `create_flow`, `get_flow_config(id, format="config"\|"model"\|"summary", path?)`, `get_flow_versions`, `restore_flow_version`, `create_flow_draft`, `update_flow_properties` (rejects sub-resource keys — see `SKILL.md` § Flow Sub-Resources), `publish_flow`, `delete_flow` |
| **Flow Structure** (9) | `get_flow_steps`, `get_flow_step`, `add_step` (returns `newStep.defaultSectionId`), `delete_step`, `rename_step(flow_id, id, new_name, target="step"\|"task")`, `move_step(flow_id, item_id, after_id, item_type="step"\|"task", target_step_id?)`, `manage_action(flow_id, step_id, action="add"\|"update"\|"replace"\|"delete", action_id?, action_data?)` (validates flow-wide eventName uniqueness; `replace` reshapes keeping the GUID), `manage_activity(flow_id, step_id, action_id, action="add"\|"update"\|"delete", activity_type?, activity_id?, properties?, condition?)` (automation on an action, e.g. `StartCrossEcosystemWork`; `update` REPLACES the whole `properties` object — send the full set; see `references/actions-and-statuses.md` § Activities), `manage_task_invites(flow_id, step_id, action="list"\|"set", invites?)` (submit-panel To/CC defaults; "set" REPLACES the list). `manage_action` / `manage_task_invites` / `delete_step` / `rename_step` accept any step GUID (`id`/`stepId`/`taskId`, resolved server-side); `move_step` is keyed on the `stepId`/`taskId` fields |
| **Flow Config** (5) | `manage_pipeline(flow_id, action, rule_id?, pipeline?, unset?)` — dataPipelines; `manage_export(flow_id, action, export_id?, export?, unset?)`; `manage_chain(flow_id, action, chain_name?, chain?, unset?)` — keyed by NAME; `manage_related_flow(flow_id, action, related_flow_id?, related_flow?)`; `manage_card_layout(flow_id, action="get"\|"update", card_layout?, unset?)` — the card `cardConfig` schema (slots + the scalar-leaf rule) is in `references/card-layout.md`. **Updates are partial PATCHes** — send only the fields you change; omitted fields are preserved (the tool reads the current item and deep-merges before saving), and `unset=True` removes the given keys. |
| **Columns** (1) | `manage_columns(flow_id, action="list"\|"add"\|"update"\|"delete", column_id?, column?)` |
| **Layout** (2) | `get_layout(id, format="full"\|"model"\|"components"\|"summary")` (summary = sections + one line per component — cheapest way to get section GUIDs), `create_layout_draft(layout_id, flow_id)` (returns draft id + sections) |
| **Component** (5) | `add_components` (verifies the write; lints known-broken configs), `update_component(layout_id, component_id, component_data, unset?, skip_merge_properties?)` (also handles type changes via `"component"` key), `batch_update_components(layout_id, updates)` (sequential, never aborts, per-item results), `replace_section_components` (destructive — include everything you keep), `delete_components` (continues past failures) |
| **Schema** (1) | `get_schema(category, schema_name?, flow_id?)` — categories: flows, components, activities, pipelines, relationships |
| **Compare** (1) | `compare(entity_type="flow"\|"layout", source_ecosystem, source_id, target_ecosystem, target_id?)` |
| **Work** (6) | `create_work`, `get_work`, `duplicate_work(id)` (clones a work honoring `flowFeatures.createAndDuplicateWork.duplicate` include/exclude paths; 404 when disabled), `list_work(flow_origin_id, skip?, limit=50, status="all"\|"inProgress"\|"completed"\|"deleted", active_step_ids?, sort_field?, sort_direction?, date_from?, date_to?)` (paginated envelope — check `hasMore`/`nextSkip`), `submit_work` (returns the post-transition step + actions), `update_work_data` (confirms without echoing the work) |
| **Search** (5) | `search_works`, `search_flows`, `search_companies`, `search_assets`, `get_flow_data_schema` — see `references/advanced-search.md`. Use these (NOT `list_work` / `list_flows` / `list_assets`) whenever the user mentions a filter, condition, sort, or projection. |
| **Asset** (7) | `list_asset_types` (**obsolete — prefer `search_flows` with `flowResourceType=Entity`**, which returns `entityType`/`thingType` too; kept as a curated/deduped fallback), `get_asset_type_properties`, `create_asset` (returns real stepName/eventName/invitation — use them verbatim in submit_work), `edit_asset`, `get_asset`, `delete_asset`, `list_assets(flow_origin_id, skip?, limit=50)` (paginated, projected rows). **For any filtered / sorted / projected asset query use `search_assets`** (Search category above; `references/advanced-search.md`), NOT `list_assets`. |
| **Apps** (6) | `request_bundle_upload` (one-time staged-upload URL for a bundle zip), `deploy_app(upload_id, name, version, app_scope, app_id?, description?, icon?)` (new app or new version; upload kept on failure for fix-and-retry), `list_apps`, `get_app(app_id)`, `update_app(app_id, …)` (metadata-only read-modify-write), `delete_app(app_id)` (soft-delete). Deploying needs the environment-orchestrator role — see `references/managing-apps.md` |
| **Dashboard** (13) | `list_dashboards`, `get_dashboard(id, format="full"\|"summary")`, `create_dashboard`, `duplicate_dashboard`, `update_dashboard_metadata`, `delete_dashboard`, `get_dashboard_draft_layout` (components projected to one line each), `add_dashboard_components`, `update_dashboard_component`, `replace_dashboard_section_components`, `delete_dashboard_components` (continues past failures), `reset_dashboard_draft_layout`, `publish_dashboard_draft_layout` |
| **Integration** (11, v4) | `list_integrations(name?)` (projected — secret values never appear), `get_integration(integration_id?, name?, format="full"\|"summary")`, `update_integration` (response is a secret-free summary with endpoint verification), `import_integrations(content, format="postman-v2.1"\|"rise-native")`, `update_integration_endpoint(integration_name, endpoint)`, `validate_integration(integration)` (read-only), `validate_integration_endpoint(endpoint, integration_parameters?)` (read-only), `test_integration_endpoint(endpoint_id, data)`, `test_integration_endpoint_in_flow(endpoint_id, flow_id, work_id, ...)`, `delete_integration(integration_id)` (physical delete — irreversible), `delete_integration_endpoint(integration_id, endpoint_id)`. The v3 `get_integration_sample` and `get_integration_decrypted` tools were retired with no v4 replacement. Load `references/integration-authoring.md` before any mutating call for the required authoring protocol. |
| **Agent** (5) | `list_agents(page=1, page_size=20, search?)` (paginated; `search` filters by name), `get_agent(agent_id)`, `create_agent(name, model, description?, system_prompt?, mcp_servers?, default_open_ai_tools?)` (returns the new `id` — also the `agent_id` for `POST /api/v1/agent/run`), `update_agent(agent_id, name?, description?, system_prompt?, model?, mcp_servers?, default_open_ai_tools?)` (PATCH — a non-empty list REPLACES, not merges), `delete_agent(agent_id)` (soft-delete). See `references/managing-agents.md`. |
